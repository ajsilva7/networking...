## TCP/IP Model 

The **TCP/IP Model** (Transmission Control Protocol/Internet Protocol) is the practical networking model used on the Internet. It defines how data is transmitted between devices over a network.
# Purpose

- Standardizes Internet communication.
- Enables devices on different networks to communicate.
- Forms the foundation of the Internet.
# 4 Layers of the TCP/IP Model

### 1. Application Layer

- Provides network services to applications and users.
- Combines the OSI Application, Presentation, and Session layers.
- 
**Protocols:**

- HTTP
- HTTPS
- FTP
- SSH
- DNS
- DHCP
- SMTP
- POP3
- IMAP
### 2. Transport Layer

- Provides end-to-end communication between hosts.
- Segments and reassembles data.
- Performs flow control and error recovery (TCP).
- Uses port numbers.
- Uses TCP or UDP depending on the application's requirements.

**Protocols:**

- TCP
- UDP
### 3. Internet Layer

- Provides logical addressing and routing.
- Determines the best path between different networks.
- Encapsulates data into packets.

**Protocols:**

- IP (IPv4/IPv6)
- ICMP
- IGMP
### 4. Network Access Layer

- Sends and receives frames over the local network.
- Uses MAC addresses.
- Handles physical transmission through Ethernet or Wi-Fi.

**Technologies/Protocols:**

- Ethernet
- Wi-Fi (802.11)
- PPP

## Step 1: Application Layer

**What happens?**

- You open Chrome.
- You type **google.com**.
- Chrome creates an **HTTP/HTTPS request**.

**Protocols**

- HTTP / HTTPS
- DNS
- SSH
- SMTP
- DHCP

**Output:** Data

⬇️

## Step 2: Transport Layer (TCP or UDP)

The application passes the data to the Transport layer.

Here you choose the protocol.

### TCP

- Reliable
- Connection-oriented
- Acknowledges received packets
- Retransmits lost packets
- Used for:
    - HTTPS
    - SSH
    - SMTP

### UDP

- Faster
- No connection
- No acknowledgements
- Best effort

Used for:

- DNS (usually)
- DHCP
- Voice calls
- Video streaming
- Online games

The transport layer adds:

- Source Port
- Destination Port
- Sequence number (TCP)
- Acknowledgement (TCP)

Now it becomes a **Segment**.

⬇️

## Step 3: Internet Layer (IP)

Now IP takes the segment.

Its job is:

- Add Source IP
- Add Destination IP
- Find the best route
- Forward packet between networks

Example

Source IP

```
192.168.1.10
```

Destination IP

```
142.250.xx.xx
```

Now it becomes a **Packet**.

⬇️

## Step 4: Network Access Layer

Now Ethernet (or Wi-Fi) prepares the packet for the local network.

It adds

- Source MAC
- Destination MAC
- FCS (Error detection)

Now it becomes an **Ethernet Frame**.

```
+-------------------------------+
| MAC Header                    |
| Packet                        |
| FCS                           |
+-------------------------------+
```

This is exactly why I told you your frame diagram is correct.

Inside the Packet are:

```
IP Header
TCP Header
Application Data
```

So the complete structure is:

```
Ethernet Frame

----------------------------------
MAC Header
----------------------------------
IP Header
TCP/UDP Header
Application Data
----------------------------------
FCS
----------------------------------
```

⬇️

## Physical Medium

The frame becomes

```
10101010101010101010
```

It travels through

- Ethernet cable
- Fiber
- Wi-Fi

⬇️

## At the Receiver

The reverse happens.

```
Bits
↓

Frame
↓

Packet
↓

Segment
↓

Application Data
```

This is called **Decapsulation**.

## TCP vs UDP

![](../TRASH/ATTACH/IMAGES/Pasted%20image%2020261120111032.png)

|Feature|TCP|UDP|
|---|---|---|
|Full Form|Transmission Control Protocol|User Datagram Protocol|
|Connection|Connection-oriented|Connectionless|
|Reliability|✅ Reliable|❌ Not guaranteed|
|Speed|Slower|Faster|
|Error Checking|Yes|Basic checksum only|
|Packet Order|Maintains order|Order not guaranteed|
|Retransmission|Yes|No|
|Acknowledgement|Yes|No|
|Overhead|Higher|Lower|
|Header Size|20–60 bytes|8 bytes|



## TCP (Reliable)

**How it works:**

1. Establishes a connection (3-way handshake).
2. Sends data.
3. Waits for acknowledgment (ACK).
4. If a packet is lost, retransmits it.
5. Delivers data in the correct order.

**Used for:**

- HTTPS (443)
- HTTP (80)
- SSH (22)
- FTP (21)
- SMTP (25)
- IMAP (143)
- POP3 (110)

**Examples:**

- Web browsing
- Email
- Online banking
- File downloads
- File transfers

---

## UDP (Fast)

**How it works:**

1. Sends data immediately.
2. No connection setup.
3. No acknowledgments.
4. No retransmissions.
5. Missing packets are ignored.

**Used for:**

- DNS (53)
- DHCP (67/68)
- VoIP
- Video streaming
- Online gaming

**Examples:**

- YouTube live streams
- Zoom/WhatsApp calls
- PUBG
- Valorant
- DNS lookups## Simple analogy

### TCP 📦

Like sending a courier:

- Send package.
- Wait for confirmation.
- If lost, send again.
- Reliable but slower.

### UDP 📨

Like making a phone call:

- Speak continuously.
- If one word is missed, keep talking.
- Fast but not guaranteed.



## Interview definition

### TCP

TCP is a **connection-oriented, reliable transport layer protocol** that ensures data is delivered **accurately, completely, and in the correct order** using acknowledgments and retransmissions.

### UDP

 UDP is a **connectionless, fast transport layer protocol** that sends data without establishing a connection or guaranteeing delivery, making it suitable for **real-time applications**.
